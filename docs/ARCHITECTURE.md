# QuoteProof architecture

## Question and non-goals
Question: "Are the words inside the quotation marks in this opinion?" Not goals: case-existence lookup, legal reasoning about whether the quote supports the argument, non-US or non-English opinions, payments, sending the brief text anywhere.

## Layers (reverse imports are forbidden and tested: `tests/architecture.test.ts`)
```
domain         pure: normalize, matchQuote (segments, ellipsis, brackets, negation check), verdict, Receipt, SHA-256, brief quote extraction (cite events, Id./supra resolution)
   ^
application    verifyQuote / verifyFromTexts / verifyBrief / creBridge (CRE payloads and log parsing), ports (Fetcher, Source), consensus (quorum over observations), evaluate (Wilson intervals)
   ^
adapters       CAP JSON text extraction, Cornell LII HTML text extraction, citation parser ("372 U.S. 335"), robots.txt parser
   ^
infrastructure robots-aware fetch (per-host Crawl-delay queue), CLI (verify, verify-brief), evaluation runner, fixture pinning, local multi-node consensus, CRE workflow entry (cre/workflow/main.ts)
```

## Data flow for one check
```
brief (stays local) --quote + citation--> verifyQuote
   citation -> CAP url, LII url   (only the citation and quote are used to build read-only GET requests)
   each source text -> matchQuote -> {found, start, end, edits[], distortion?}
   all sources found, same edits, no distortion -> PASS
   any missing -> HOLD/NOT_IN_OPINION · sources disagree -> HOLD/SOURCE_DISAGREE
   fewer than minSources -> HOLD/INSUFFICIENT_SOURCES · negation dropped/inserted -> HOLD/DISTORTION
   Receipt{citation, quote, verdict, reasons, edits, sources[{id, textSha256, found, start, end}], checkedAt}
   receiptHash = sha256(canonical JSON without checkedAt)
```
Only `{verdict, reasons, receiptHash, sourceSummary}` leaves the node (returned by the workflow and put in an EVM report; the brief and the opinion text are never sent).

## Whole-brief check (v3)
`bun run verify-brief <file>`: `domain/brief.ts` extracts (quote, citation) pairs from the text, `application/verifyBrief.ts` runs `verifyQuote` per pair and builds the table + one summary line. Read requests are built from the citation only; a test asserts that no brief word appears in any request URL. v4: `Id.`/`supra` are resolved against the nearest previous citation (reasons `ID_*`, `UNRESOLVED_SUPRA` when not), and `--cre-payload <dir> [--cre-simulate N]` writes one `{citation, quote}` payload per checked row and can run `cre workflow simulate` on it (`application/creBridge.ts` + `infrastructure/verifyBriefCli.ts`), comparing the CRE consensus hash with the local receipt hash.

## Reads and robots.txt (v4)
`infrastructure/politeFetcher.ts` fetches robots.txt once per host, waits the host's `Crawl-delay` between requests (a per-host queue, so concurrent callers also wait), and in strict mode does not request disallowed paths. LII: 10 s. CAP's robots.txt says `Disallow: /`; the user-initiated CLI notes this and still sends one GET per cited opinion (README Limits gives the reasoning and the strict switch).

## CRE workflow
`cre/workflow/main.ts`: HTTP trigger -> `runInNodeMode(fetchBoth, consensusIdenticalAggregation)`. The workflow is written so that each node reads both sources and the nodes agree on the identical observation (`consensusIdenticalAggregation`); in our only runs, `cre workflow simulate` executes it once per simulated node on this machine, not on a CRE network. The default CLI does not call CRE. The consensus rule is also re-implemented locally (`src/infrastructure/localConsensus.ts`, quorum 3 of 4) for runs without an account.
Status: compiled to WASM; `cre workflow simulate` succeeded for the genuine and altered payloads (2026-10-30, exit 0), including the EVM `writeReport` (`cre/workflow/onchain.ts` builds the ABI report `(bytes32 receiptHash, uint8 verdictCode, string reasons)`); also executed in the CRE SDK test runtime; no live deployment on the CRE network. The Sepolia receiver (`cre/receiver/QuoteProofReceiver.sol`) pins the forwarder in its constructor (mock forwarder from Chainlink's Forwarder Directory) and rejects other callers; a test runs its bytecode in an EVM. See README for the Sepolia transaction measurement.
